<Aside title="In short">
Auto mode lets the model edit the project, run commands, and delegate without asking, and it
still asks before the network. It can only be entered when a sandbox works on this machine, and
every command runs inside that sandbox. Because no one reads tool output before the model does,
auto mode is also the only mode in which the trust gate screens that output for prompt injection.
Three things hold it up: the mode table, the sandbox, and the classifier. Each is a setting, and
the classifier is one you choose: any chat model on any provider you use, or a judgment model.
</Aside>

## What auto mode decides

Every tool carries a policy class. With no rule written for a call, the mode decides by class.
This is the auto row of the mode table next to the two modes on either side of it:

| Class | `accept-edits` | `auto` | `bypass` |
|---|---|---|---|
| `read` | allow | allow | allow |
| `write` | inside the project, else ask | inside the project, else ask | allow |
| `execute` | ask | inside the sandbox, else ask | allow |
| `network` | ask | ask | allow |
| `delegate` | ask | allow | allow |
| `state` | allow | allow | allow |
| no class | as `execute` | as `execute` | allow |

Source: <Receipt path="src/core/permissions/modes.ts" symbol="MODE_DEFAULTS" />.

Two of these cells are conditions rather than answers. `inside` allows a write when every path in
the call resolves under the project root, and asks otherwise. `sandboxed` allows a command when the
session has a sandbox, and asks otherwise. The engine turns each into an allow or an ask with a
reason the transcript records, such as "auto mode allows commands inside the sandbox".

Source: <Receipt path="src/core/permissions/engine.ts" symbol="modeDefault" />.

Rules still win. A `deny` in `permissions.deny` refuses a call in auto mode as in any other, an
`ask` rule asks, and a tool marked `alwaysAsks` asks every time. The mode is only the default for
calls no rule reaches.

## Entering auto mode

A session enters auto mode in one of three ways, and all three pass the same check:

- `permissions.mode: "auto"` in `.jamcli/config.json`, which sets the mode a session starts in.
- `--permission-mode auto` on the command line.
- `/mode auto` in the interface, which calls `setPermissionMode` on the runtime.

The check is that a sandbox exists. Without one the switch is refused with the reason "auto mode
runs commands without asking only inside a sandbox, and no sandbox is available here", and a
session that asked for auto mode in a file starts in default mode and says so in a notice.

Source: <Receipt path="src/core/permissions/modes.ts" symbol="modeRefusal" />,
<Receipt path="src/core/runtime/index.ts" symbol="setPermissionMode" />.

Switching modes rebuilds the tool set, the system prompt, and the agent, so what the model is
offered and what screens its tool output change on the next turn, not the next session.

## The sandbox

The sandbox is detected once per session: bubblewrap on Linux, Seatbelt on macOS, and none
anywhere else. Detection probes that the tool can actually start, because a container without
namespaces has `bwrap` installed and cannot use it. The reason for the outcome is kept and shown
in the status line as `no sandbox` when there is none.

Source: <Receipt path="src/core/sandbox/detect.ts" symbol="detectSandbox" />.

Inside the sandbox a command gets:

- Read access to the filesystem, except a list of credential paths that are hidden: `~/.ssh`,
  `~/.aws`, `~/.kube`, `~/.netrc`, `~/.npmrc`, the Docker and 1Password sockets, and more.
- Write access to the project root, the temporary directory, and nothing else.
- No network, and on macOS no Unix sockets either, since one reaches the Docker daemon as easily
  as a port.
- An environment with credential-looking variables removed.

Source: <Receipt path="src/core/sandbox/seatbelt.ts" symbol="seatbeltProfile" />,
<Receipt path="src/core/sandbox/bwrap.ts" symbol="bwrapSandbox" />,
<Receipt path="src/core/sandbox/paths.ts" symbol="DEFAULT_HIDDEN" />.

Every one of these is a setting under `sandbox` in configuration:

| Setting | Default | Effect |
|---|---|---|
| `enabled` | on where a sandbox works | `false` turns it off, which also makes auto mode unavailable. |
| `network` | off | Lets sandboxed commands reach the network. |
| `writable` | none | Directories besides the project and temp that commands may write. |
| `hidden` | none | Paths hidden in addition to the defaults. |
| `env` | `scrubbed` | `scrubbed` drops credential-looking variables; `minimal` passes only what a shell needs. |
| `env_passthrough` | none | Variables passed by name even when they look like credentials. |

Source: <Receipt path="src/core/config/schema.ts" symbol="SandboxSettingsSchema" />.

## The trust gate

In every other mode a person sees a tool's output in the transcript before the model acts on
it. In auto mode the model acts first. So auto mode is the only mode in which the trust gate runs:
after each batch of tool calls, and before the results enter context, a second model reads them
and says which ones are prompt injection.

What happens on each turn:

1. The session's own state, such as the todo list the model wrote, is left out: it is not from
   outside, and nothing in it needs screening.
2. Results with the same tool and the same normalised text are sent once. Each duplicate takes the
   verdict of the first, so it is kept or withheld with it, never withheld for being a duplicate.
3. The rest go to the classifier in one request. Each result is cut to 4,000 characters, keeping
   the beginning and the end, and the task description the classifier sees is cut to 2,000.
4. The classifier answers, per result, a relevance score from 0 to 1, an injection flag, and a
   short reason. How it is asked depends on what kind of model it is; see below.
5. A result flagged as an injection is withheld. A result scoring under the threshold is withheld
   as not relevant. The model sees a one-line note in place of each, and the transcript records
   which tool and why.
6. A result the classifier did not mention is kept. If the request fails, times out, or returns
   nothing usable, every result is kept and the failure is reported. The gate fails open.

Every request is kept in the session log: what the classifier was sent and answered, or
why the request failed, each result's verdict and fate, and the text of a withheld result.
The model never sees any of it; `/copy debug` shows it.

Source: <Receipt path="src/core/trust/index.ts" symbol="screenToolResults" />,
<Receipt path="src/core/agent.ts" symbol="screen" />.

### Which model classifies

The classifier is `trust.model` in configuration, and choosing it is yours. Nothing picks one for
you: the classifier reads every tool result in auto mode, so which model does that, where it runs,
and what it costs are decisions JamCLI does not make on its own. Until it is set, the gate stays
off and auto mode says so once per session. Outside auto mode nothing is screened and nothing is
said.

Source: <Receipt path="src/core/runtime/model.ts" symbol="trustModelRef" />,
<Receipt path="src/core/runtime/model.ts" symbol="trustClassifier" />.

The value is `provider:model` on any provider the session knows, or a bare model name, which
means Ollama. Two kinds of model can sit behind it, and the gate treats them through one seam:

| Kind | Example values | How it is asked |
|---|---|---|
| A chat model | `ollama:qwen3:1.7b`, `openrouter:meta-llama/llama-guard-4-12b`, `anthropic:claude-haiku-4-5-20251001`, `myproxy:small` for an entry in `api_registry.endpoints` | One prompt holding every result, escaped so a result cannot forge its own delimiter, with reasoning off. It answers one JSON object per result. |
| A judgment model | `typesafe:jev-latest` | The turn is sent as state, with two yes-or-no questions per result: is it an injection, and is it relevant. It answers each with a probability. |

Source: <Receipt path="src/core/trust/index.ts" symbol="Classifier" />,
<Receipt path="src/core/trust/index.ts" symbol="chatClassifier" />,
<Receipt path="src/core/trust/jev.ts" symbol="jevClassifier" />.

A chat model needs whatever its provider already needs: a key stored with `jamcli auth set`, a
`key_env_var`, or a local Ollama. For Ollama, `think: false` is sent explicitly, because its
thinking models think unless told not to, and a thinking classifier turns a two second check into
a minute.

Jev is TypeSafe's System One model. It does not generate text; it returns typed answers and
probabilities, which is exactly what the gate needs, and it answers in a few hundred
milliseconds. It takes a key, from `jamcli auth set typesafe`, `TYPESAFE_API_KEY`, or
`api_registry.typesafe.key_env_var`. A result is withheld as an injection at a probability of
0.5 and above, and its relevance probability is compared with `trust.threshold` like any other
score.

Source: <Receipt path="src/core/trust/jev.ts" symbol="buildJevRequest" />,
<Receipt path="src/core/trust/jev.ts" symbol="parseJevAnswers" />,
<Receipt path="src/core/providers/factory.ts" symbol="resolveApiKey" />.

The classifier's requests are counted under its own model in the session's spend, so what the
gate costs is visible apart from what the conversation costs. `jamcli doctor` checks the
classifier as a model in use, next to the session model. A chat model is asked to describe itself.
Jev is asked one real judgment on a planted injection, and the check warns when it does not flag
it.

Source: <Receipt path="src/cli/doctor.ts" symbol="modelsInUse" />,
<Receipt path="src/cli/doctor.ts" symbol="judgmentCheck" />.

### Settings

| Setting | Default | Effect |
|---|---|---|
| `trust.model` | none: auto mode says the gate is off | The classifier, as `provider:model` on any configured provider, or `typesafe:jev-latest`. |
| `trust.threshold` | 0.3 | Relevance below which a result is withheld. `0` keeps every result that is not an injection. |
| `trust.enabled` | on | `false` turns the gate off in every mode, and the off state shows in configuration. |
| `trust.dedupe` | on | Identical results are sent once, each duplicate taking its twin's verdict. `false` sends every one. |

Source: <Receipt path="src/core/config/schema.ts" symbol="trust" />,
<Receipt path="src/core/trust/index.ts" symbol="DEFAULT_THRESHOLD" />.

## What is worth testing

The gate is only as good as the classifier, and a classifier is a model reading results it was
never trained on. These are the questions the settings above leave open, and what was seen when
they were first tried on a Mac, on one turn holding a relevant file read, a planted injection, an
unrelated recipe, and a relevant grep hit.

**Which model to trust with the job.** Local chat models under a billion parameters echoed the
example object back and judged one result of three. `ollama:qwen3:1.7b` was the smallest that
flagged the injection, in under two seconds, and `ollama:granite4.2:3b` the smallest that also
scored relevance correctly. `typesafe:jev-latest` scored all four results correctly in half a
second: 98% injection on the planted one, 93% to 95% relevance on the two that mattered, 3% on
the recipe. A hosted chat model on OpenRouter or Anthropic is a middle path: capable, but a full
model round trip on every tool turn. A purpose-built encoder detector such as Meta's Prompt Guard 2
would need its own classifier kind, like Jev has.

**Whether relevance filtering helps or hurts.** The small local models that catch an injection
scored the relevant file read at 0, which the default threshold would withhold. Jev's relevance
scores were well separated. Setting `trust.threshold` to `0` keeps injection screening and gives
up relevance filtering, which is the right setting for a classifier whose relevance scores you
have not checked on results you know are relevant.

**What a real session withholds.** Every removal is a warning in the transcript naming the tool
and the reason. A session with many removals and no real injections says the threshold is too
high or the model too small. A session with none says nothing, which is why the planted injection
test matters.

**Sandbox gaps a project needs.** A build that writes outside the project, needs the network, or
reads a credential the sandbox hides fails inside auto mode with a note that names the sandbox.
`writable`, `network`, and `env_passthrough` open each gap on purpose, and the wider each is
opened the less auto mode protects.

A change to the chat prompt, the threshold, or the truncation bounds is a change to
`src/core/trust/index.ts`; a change to the questions Jev is asked is in `src/core/trust/jev.ts`.
A new kind of classifier is a new implementation of `Classifier` and a branch in
`trustClassifier`. The tests under `src/core/trust/__tests__/` and
`src/core/runtime/__tests__/runtime.test.ts` are where the contract is pinned.
